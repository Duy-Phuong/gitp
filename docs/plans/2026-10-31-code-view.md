# Code View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Code tab in gitp that opens, edits and navigates the checked-out project (Java, JS, TS, Python) with zero setup: explorer, quick open, CodeMirror editing with auto-save, go to definition, back/forward, find usages, call hierarchy and gitignore-aware full-text search.

**Architecture:** A new library crate `gitp-code` (tree-sitter symbol index, resolver, ripgrep-crate search, ignore-aware file walk) is bridged by `crates/gitp-gui/src/code.rs` Tauri commands with one lazily created `CodeState` per open repository, kept fresh by the existing watcher. The webui gets a `code/` module family under `views/` with a CodeMirror 6 editor, a tab model, a navigation stack and three panels (search, usages, hierarchy).

**Tech Stack:** Rust (tree-sitter 0.25 + the four grammar crates, `ignore`, `grep-regex`, `grep-searcher`, `rayon`), Tauri 2, TypeScript, CodeMirror 6 (`codemirror`, `@codemirror/lang-java`, `@codemirror/lang-javascript`, `@codemirror/lang-python`), vitest + happy-dom, cargo test.

**Spec:** `docs/specs/2026-10-31-code-view-design.md` — read it first; where this plan and the spec's scaffolding differ, the spec's "Points settled during the builder check" section wins, then this plan.

## Global Constraints

- Work on a branch `feat/code-view` cut from `main`; gitp lands features by merging `refs/heads/feat/*` into `main`.
- Build and test outside the sandbox for cargo (see memory: cargo needs sandbox off). Frontend: `cd crates/gitp-gui/webui && npm test`, `npm run typecheck`, `npm run lint`. Backend: `cargo test --workspace`.
- Paths over the wire are repository-relative, `/`-separated, as everywhere in gitp. Lines and columns are **0-based**; columns are **UTF-16 code units**.
- Files over `gitp_core::EDIT_MAX_BYTES` (2 MiB) are never opened; reuse `Repo::read_text_file` / `write_text_file`, which enforce it.
- Code-view saves bypass `with_recorded_files` (no Undo entry). Local History remains the safety net.
- Auto-save delay is 1 500 ms. Search and reference lists cap at 2 000 with a `truncated` flag. Navigation history caps at 100 stops; a caret move of more than 10 lines is a stop.
- Walk: `hidden(false)`, `git_ignore(true)`, `git_global(true)`, `git_exclude(true)`; `.git` skipped. Gitignored paths are absent everywhere.
- Watcher batches with more than 500 worktree paths trigger a full rebuild instead of per-path reindex.
- Shortcuts (Mod = Cmd on macOS, Ctrl elsewhere): `Mod+P` quick open, `Mod+Shift+F` find in files, `Mod+S` save, `F12` / `Mod+click` definition, `Mod+Alt+Left/Right` back/forward, `Alt+F7` usages, `Ctrl+Alt+H` hierarchy, `Mod+Shift+W` close tab, `Mod+Shift+E` Code tab. `Mod+K` stays Quick Launch.
- Every new `api.ts` wrapper has a preview-mode (`!isTauri()`) mock, as every existing one does.
- Commit after each task with a conventional message ending in `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **A CRLF file edited in the Code tab** must save back with CRLF, unchanged except where edited — test pinned to Task 7 (`write_keeps_crlf`).
2. **An invalid regex in Find in files** (`(`) must show the matcher's message, not a crash or an empty list that looks like "no results" — Task 6 (`invalid_regex_is_an_error`) and Task 15 (`shows_the_error_text`).
3. **Clicking a binary, oversized or non-UTF-8 file in the explorer** must toast an error and leave the current tab as it was — Task 12 (`open_failure_leaves_tabs_untouched`).
4. **A file renamed or deleted on disk while open** must keep its tab, read-only with a strikethrough name, and never auto-save a resurrected copy — Task 17 (`deleted_file_tab_is_read_only`).
5. **Cmd+click on a keyword, string or comment** must do nothing and not push a navigation stop — Task 5 (`definition_outside_an_identifier_is_empty`) and Task 13 (`no_result_pushes_nothing`).
