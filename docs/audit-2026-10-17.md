# gitp bug audit — 2026-10-17

**Status (same day): all 35 findings fixed in the working tree, uncommitted.** 170 Rust tests and 68 web tests pass; clippy and tsc are clean. Deviations: O2 uses per-path `:(literal)` pathspecs instead of `GIT_LITERAL_PATHSPECS` (the env var breaks `git stash -u`); the U1 index precondition compares index *entries* (path, mode, oid, stage), not bytes, because `git status` rewrites stat data.

Scope: conflict resolution, switching (repo tabs, files, branches), undo/redo, and the rest of the app.
Every finding was verified by reading the code; items marked **repro'd** were also reproduced in a scratch repo.
Nothing in the repo was changed. Proposed fixes are sketches, not patches.

Paths: `core/` = `crates/gitp-core/src`, `gui/` = `crates/gitp-gui/src`, `web/` = `crates/gitp-gui/webui/src`.

## A. Undo / redo

### U1 (HIGH) — Undo/redo never check the repo is still in the recorded state
`core/undo.rs:260-325`, `gui/lib.rs:1103-1144`.
`Repo::undo` applies the stored target blindly. Nothing compares the current HEAD, index, tag, branch or file bytes to the recorded `after` (undo) or `before` (redo).
**Repro'd:** GUI commit c2 → commit c3 from the embedded terminal → Undo "Commit" → `reset --soft c1` drops c3 from the branch.
Same shape for `IndexChanged` (restores an index that no longer matches HEAD), `Switched`, `UpstreamChanged`, `Discarded` (overwrites edits the user made since).
**Fix:** add `Repo::can_undo(&Undoable)` / `can_redo` and call them at the top of `undo_impl`/`redo_impl`:
- HeadMoved: `head_commit_id() == after` / `== before`; refuse during any merge/rebase/cherry-pick/revert session.
- Switched: `head_ref_name() == after` / `== before`.
- BranchCreated: HEAD on `name` and `branch_commit_id(name) == at`.
- BranchesDeleted: each absent / each present at `oid`. BranchRenamed: `new` exists, `old` absent / reverse.
- IndexChanged: `.git/index` bytes equal the `after` / `before` snapshot.
- TagCreated/TagDeleted: `tag_ref_target(name) == target` / tag absent.
- StashDropped: `oid` not on / on the stack. UpstreamChanged: `branch_upstream(branch) == after` / `== before`.
- Discarded: each file's bytes equal the `after` / `before` side.
On mismatch: error "repository changed since that action; nothing was undone" and clear the slot. Ideally also run the check in `workspace_snapshot_impl` so the toolbar greys out a stale Undo.

### U2 (HIGH) — A paused interactive rebase is recorded as `HeadMoved`; undo corrupts the rebase
`core/rebase.rs:172-180`, `gui/lib.rs:1437-1446`, `gui/lib.rs:822`.
`interactive_rebase` returns Ok when it stops on `edit`/conflict; `with_recorded_head_move` records the detached mid-rebase HEAD as `after`.
**Repro'd:** rebase -i with `edit` → Undo → `reset --keep <old tip>` succeeds, todo remains, `rebase --continue` fails with "Could not apply". Branch ref never moved back.
Also: an older slot survives into a conflict session. Git blocks a soft/keep reset during a merge, but `IndexChanged` undo copies a file over `.git/index` (`core/undo.rs:211-220`) and wipes the conflict stage entries; `Discarded`/`Switched`/`BranchCreated` are unprotected too.
**Fix:** in `with_recorded_head_move`, record nothing and clear the slot if `rebase_in_progress()` or a conflict session exists after `f`. Refuse undo/redo while `.git/{rebase-merge,rebase-apply,MERGE_HEAD,CHERRY_PICK_HEAD,REVERT_HEAD}` exists; disable the buttons in the UI when `snap.conflict`/`snap.rebase` is active.

### U3 (HIGH) — Undo "Create branch" force-deletes without checking the branch still points at `at`
`core/undo.rs:264-267`, `gui/lib.rs:941-966`, `gui/lib.rs:1163-1165`.
Commits made on the new branch (terminal, stash pop, conflict commit) are lost by `branch -D`. Also `at` is stored as the user's rev string (`origin/main`, tag), so redo recreates the branch wherever that ref points *now*.
**Fix:** U1 guard; resolve `at` to a SHA when recording.

### U4 (MEDIUM-HIGH) — Index snapshots use two fixed paths that no-op/failed ops overwrite
`gui/lib.rs:838-839, 848-876`.
`UNDO_INDEX_BEFORE` is written before knowing whether the op will be recorded. A no-op "Stage all" or a failed stage replaces the snapshot the armed `IndexChanged` points at → Undo "Stage" silently restores the *current* index (does nothing), and Redo is armed for a no-op.
**Fix:** snapshot to a temp name and `rename` into a fresh unique name only when recording; or store a content hash in the `Undoable` and verify on undo (gives U1 for free). Also clean up snapshot files, check `.git/index.lock` in `restore_index`, and fix the stale comment at `gui/lib.rs:845-846`.

### U5 (MEDIUM) — Mutating commands that neither record nor clear the undo slot
Not recorded, not calling `clear_undo` (only `stash_impl`/`stash_pop_impl` do): `fast_forward_branch_impl` 1405, `fetch_and_update_branch_impl` 1395, `finish_conflict_impl` 699, `abort_conflict_impl` 694, `rebase_continue/skip/abort_impl` 1455-1465, `create_backup_branch_impl` 1262, `stash_apply_impl` 551 (sidebar apply *and* pop), `stash_files_impl` 592, `resolve_conflict*_impl` 684-691, `add_to_gitignore_impl` 607, `stash_rename_impl` 577.
**Scenario:** GUI commit → sidebar Fast-forward → Undo "Commit" drops the fast-forwarded commits.
**Fix:** U1 guard is the real fix; additionally route these through a helper that clears (or records) the slot. Fast-forward and finish_conflict are plain `HeadMoved`s.

### U6 (MEDIUM) — `Discarded` snapshots worktree bytes only, but discard also resets the index
`core/file_ops.rs:30-46`, `gui/lib.rs:970-1000`, `core/undo.rs:374-401`.
**Repro'd:** file `MM f` (staged + unstaged hunk) → Discard → Undo → worktree restored but index at HEAD; the staged hunk is gone. Staged-new file comes back untracked.
Edge: `read_workfile(p).ok().flatten()` turns a read error into `None`, so undo would then delete the file; `fs::write` through a symlink writes the target.
**Fix:** snapshot the index around discards (with U4 fixed), or make "discard unstaged" use `git checkout -- path` (from the index) so a worktree-only snapshot suffices.

### U7 (MEDIUM) — `BranchesDeleted` undo isn't idempotent; a partial failure can never be retried
`core/undo.rs:268-284`. `?` on the first `git branch <name> <oid>` failure; on retry already-recreated branches fail with "already exists".
**Fix:** treat a branch that already exists at `oid` as success; collect errors and report after the loop.

### U8 (LOW-MEDIUM) — Tag restore force-overwrites; tag undo deletes blindly
`core/undo.rs:290, 328-333`. **Repro'd:** delete tag v1 → user re-creates v1 elsewhere → Undo retargets the user's v1. **Fix:** U1 guard; `force=false`.

### U9 (LOW) — Reset undo semantics
`gui/lib.rs:1229-1231`. Every reset mode records `soft:false` → undo uses `--keep`; after a `--soft` reset a staged new file comes back untracked. "Undo Reset" after `--hard` can't restore worktree/index. **Fix:** record soft resets as `soft:true`; label hard-reset undo "branch tip only" or snapshot index+worktree.

### U10 (LOW)
- `checkout_remote_impl` (`gui/lib.rs:492`) records only `Switched`; undo leaves the new local branch.
- `pull_impl` (`gui/lib.rs:506-518`) reads `before` and `path` under different locks; a tab switch in between pairs a foreign `before`. Read both under one lock.

### UI side of undo (from the web review)
- **Cmd/Ctrl+Z / Y bypass the busy guard** (`web/main.ts:3646-3655` → `1457-1489`). Buttons disable on `actionsBusy`, the shortcut and Quick Launch items don't. Pull/push run with the backend lock released, so undo really executes mid-pull. Also fires while a modal is open; two quick presses issue two undos. **Fix:** `if (actionsBusy || changesView?.isBusy()) return;` and set `actionsBusy`; bail when `.modal-overlay, .ql-overlay` exists.
- Closing the last tab leaves `undoLabels` stale (see W8).

## B. Conflict resolution

### C1 (HIGH) — Saving a resolved file drops the trailing newline
`web/conflict.ts:182-187` (`splitLines` pops the trailing empty element), `web/conflict.ts:274-282` (`assembleResult` joins with `\n`, never re-adds it), `core/conflict_ops.rs:147`.
Every file saved through the 3-way editor ends without `\n`, so the merge commit introduces a "\ No newline at end of file" change in every resolved file.
**Fix:** `return out.length ? out.join("\n") + "\n" : ""` (or remember whether ours/theirs ended with a newline and mirror it).

### C2 (HIGH) — Delete/modify conflicts cannot be resolved by taking the deletion
`core/conflict_ops.rs:155-159`, `web/conflict.ts:249-266`.
**Repro'd:** `DU f` → `git checkout --ours -- f` fails with "path 'f' does not have our version". In the editor the deleted side shows as empty, and accepting it writes an **empty file** and `git add`s it, instead of deleting.
**Fix:** in `resolve_conflict_side`, when the chosen stage is absent (`git show :2:path` fails) run `git rm --cached -- path` + delete the worktree file. In the UI, when `sides.ours`/`sides.theirs` is `null`, show "deleted on this side" and make Save with an empty result call a new `resolve_conflict_delete` instead of writing an empty file.

### C3 (MEDIUM) — Leftover `pendingCherryPicks` fire on a later, unrelated conflict resolution
`web/main.ts:2294-2329, 3812-3827, 2412-2424`.
The batch queue is cleared only by the resolver's own Abort or a non-conflict error. Not by the banner Abort, a terminal `cherry-pick --abort`, rebase abort, tab switch/close, or finishing in Local Changes. `onDone(msg,false)` always resumes.
**Scenario:** cherry-pick 3 → #1 conflicts → banner Abort → later a merge conflicts → Finish → the 2 leftover commits are cherry-picked onto the merge.
**Fix:** clear the queue in `abortConflictAction`, in `applyConflictStatus` when conflict becomes null or kind ≠ cherry-pick, in `switchRepo`/`closeRepoTab`; in `onDone` resume only if the finished session was this batch's cherry-pick in the same repo.

### C4 (MEDIUM) — Conflict view never refreshes from external changes
`web/main.ts:1057-1071, 3425-3430`. `refreshFromDisk` and `onTerminalCommand` never call `conflictView.reload()`. Resolving a file in the terminal leaves it listed as conflicted and Finish disabled until you leave and re-enter.
**Fix:** `if (state.view === "conflict") void conflictView?.reload()` in both; call `conflictView.reset()` when the session ends outside the resolver (see W3).

### C5 (MEDIUM) — Pull / stash pop conflicts aren't recognised
`web/main.ts:1491-1504, 1563-1593`. The catch only shows "Pull failed"; no `refreshConflictStatus`/`refreshRebaseStatus`/`loadSidebar`, no "Resolve Conflicts" action, unlike `runBranchOp`/`runCommitOp`. The banner appears only after the next pointerdown.
**Fix:** mirror `runCommitOp`'s catch; treat rebase `paused_for: "conflict"` as in-conflict too (Pull with rebase).

### C6 (MEDIUM) — "Edit File" edits are silently discarded by Save
`web/conflict.ts:735-745`. Save assembles the result from the chosen chunks only; the on-disk text (edited externally via "Edit File") is never read. Only the bulk "Mark all resolved" uses the working file.
**Fix:** add a per-file "Mark resolved as on disk" action (same check as `markAllResolved`), and/or warn when the working text has no markers but differs from the assembled result.

### C7 (LOW-MEDIUM) — Accepting the same side twice duplicates its lines
`web/conflict.ts:715-720`. `acceptSide` appends; two clicks on ≫ insert ours twice. Appending is wanted for "ours then theirs", not for the same side.
**Fix:** track which sides were accepted per chunk and disable/ignore a repeat of the same side.

### C8 (LOW) — Rebase summary says "Rebasing HEAD"
`core/conflict_ops.rs:66-74, 212-218`. HEAD is detached during a rebase. **Repro'd.** **Fix:** read `.git/rebase-merge/head-name` (strip `refs/heads/`), fall back to `rebase-apply/head-name`.

### C9 (LOW) — Commit-box prefill re-applies and never clears
`web/main.ts:2363-2369`. Every snapshot during a merge re-fills the box if the user cleared it; after a terminal `merge --abort` the "Merge branch …" text stays and is used by the next commit. **Fix:** prefill once per session (`prefilledFor = summary`); clear on the null transition if the box still equals the prefill.

### C10 (LOW) — Unmerged files appear as ordinary "Modified" in Local Changes
`core/status.rs:220` maps `U` to `Modified`, so a `UU` file shows in both Staged and Unstaged with no conflict marker. **Fix:** add a `Conflicted` kind (or flag) and render it distinctly / route to the resolver.

## C. Switching (repo tabs, files, branches)

### W1 (HIGH) — Local Changes diff pane goes stale after hunk staging, external edits, repo switches
`web/changes.ts:165-174, 188-190` (`sameSummary` skip), `web/changes.ts:129-139, 201-232`.
The skip compares only path/old_path/status, so content changes are never re-fetched.
**Repro:** 2-hunk file → Stage hunk 0 → hunk 0 stays visible with a live Stage button (second click: `git apply` error / wrong hunk). Also: external edit + focus refresh shows old hunks; switching to a repo where the same path is modified shows repo A's hunks for repo B's file.
**Fix:** invalidate `selectedDiffSummary` in `run()`/`runStaging` before `reload()` and in a new `reset()`; keep the skip only for the pure view-switch path.

### W2 (HIGH) — `checkout_branch` prefers a same-named tag and points HEAD at `refs/tags/...`
`core/checkout.rs:13, 33-47`. `revparse_ext` uses DWIM order (tags before heads) and the code then makes HEAD symbolic to *whatever* ref came back.
**Repro'd:** branch `feature` and tag `feature` → checkout → `symbolic-ref HEAD` = `refs/tags/feature`; subsequent commits move the tag. `create_branch` is affected the same way.
**Fix:** try `find_branch(name, Local)` first; only attach HEAD symbolically when `reference.is_branch()`, else `set_head_detached`.

### W3 (HIGH) — Per-view state is never reset on repo tab switch/close
`web/main.ts:693-729`, `web/changes.ts:107-115`, `web/conflict.ts:190-224`.
`changesView` and `conflictView` are singletons. Commit subject/body, `amend` + `amendFiles`, `selected`, `checked`, `collapsed` leak from repo A to B.
**Repro:** repo A → tick Amend → switch to B → Staged lists A's HEAD files, Commit enabled → **amends B's HEAD with A's message**. The resolver likewise keeps A's `initial` set, message and `resStore`.
**Fix:** add `reset()` to `ChangesHandle`; call `changesView.reset(); conflictView.reset(); pendingCherryPicks = []` from `applyWorkspace` when the active path changes and from the zero-repos branch of `closeRepoTab`.

### W4 (MEDIUM) — Sidebar refresh repaints the full log over active search results
`web/main.ts:1161-1170`. Repaint branch ignores `logSearchQuery()`. **Repro:** search → click a result → 3s → click sidebar → full log replaces results. **Fix:** `if (logSearchQuery()) void updateLogView(); else renderLog(...)`.

### W5 (MEDIUM) — Closing the last repo tab leaves stale banners, lists, undo labels
`web/main.ts:709-720`. `state.rebase`, `state.conflict`, `undoLabels`, `changesView`, `terminal` cwd are not reset; banners stay with live buttons that hit "no active repo". **Fix:** reset them and re-render banners in that branch.

### W6 (LOW) — `jumpToCommit` can be undone by the background `refreshHistory`
`web/main.ts:1293-1311, 1120`. If the fingerprint changed, the refresh replaces rows with page 1 and selection jumps to `rows[0]`. Also `refreshHistory`/`loadMoreCommits`/`loadDownTo` never compare the captured `repoPath` with the current one after awaits. **Fix:** skip the refresh from `jumpToCommit`'s `showView`, add a request token / repoPath guard.

### W7 (LOW) — `toggleAmend` on→off race
`web/changes.ts:707-733`. Untick before `fetchHead` resolves → HEAD message prefilled with Amend off → duplicate-message commit. **Fix:** re-check `amend` after the await.

### W8 (LOW) — detail.ts re-context fetch: unguarded error path, duplicate requests
`web/detail.ts:276-289`. `.catch` writes "Diff failed" without the key guard; every `render()` while `recontexted` is unset refetches. **Fix:** guard the catch, add an in-flight key.

## D. Other core issues

### O1 (HIGH) — Interactive rebase deletes its scratch dir while the rebase may be paused
`core/rebase.rs:144-150, 176`. Rewords are `exec git commit --amend -F <tmpdir>/msgN.txt`; `remove_dir_all` runs as soon as the first `git rebase -i` returns, including on an edit/conflict stop.
**Repro'd:** `[edit c1, reword c2]` → continue → "could not read log file", message unchanged, status shows a bogus `paused_for: "edit"` with `current_sha: None`.
**Fix:** keep message files under `.git/gitp-rebase/<id>/` and delete only when `!rebase_in_progress()`; or use `exec git commit --amend -m '<shell_quote(msg)>'`. Consider `paused_for: "exec"` when `stopped-sha` is absent.

### O2 (HIGH, edge input) — Paths are passed as pathspecs; glob chars hit other files
`core/file_ops.rs:29-89`, `core/hunk.rs:62`, `core/remote.rs:74,79`, `core/status.rs:201`, `core/diff.rs:125`.
`a[1].txt` also matches `a1.txt`. **Repro'd:** `discard_files(["a[1].txt"])` reverts `a1.txt`; `stage_hunk("a[1].txt",0,..)` stages a hunk of `a1.txt` (`Patch::from_diff(&diff, 0)` takes delta 0, not the one matching `path`).
**Fix:** `GIT_LITERAL_PATHSPECS=1` in `run_git*`; `opts.disable_pathspec_match(true)` in `staging_diff`/`commit_file_diff`; in `hunk_patch` pick the delta whose path equals `path`.

### O3 (MEDIUM) — `--update-refs` is a silent no-op in `interactive_rebase`
`core/rebase.rs:161-166`. The `cp` sequence editor replaces git's todo, dropping its `update-ref` lines. **Repro'd:** dependent branch unchanged. **Fix:** emit `update-ref refs/heads/<b>` lines yourself (branches pointing at each step's SHA via `for-each-ref --points-at`), or drop the option.

### O4 (MEDIUM) — `save_stash_patch` loses untracked files and may corrupt the patch
`core/stash_ops.rs:53-56`. `stash show -p` omits untracked files that `stash()` saved with `--include-untracked`; `run_git` appends stderr and trims. **Fix:** `run_git_raw(["stash","show","-p","--include-untracked", ref])` and write raw stdout.

### O5 (MEDIUM-LOW) — `remote_branch_exists` matches by ref tail
`core/branch_ops.rs:97`. `ls-remote --heads origin foo` also matches `bar/foo`. **Fix:** query `refs/heads/<name>` (as `tag_ops.rs:95` already does).

### O6 (LOW-MEDIUM) — `unstage_all` fails on an unborn branch
`core/remote.rs:90`. `git reset -q HEAD` → "unknown revision". **Fix:** `git reset -q`.

### O7 (LOW) — `checkout_commit` doesn't detach for branch names; detached-HEAD push message never fires
`core/commit_ops.rs:38` → use `checkout --detach`. `core/remote.rs:124-129`: `shorthand()` returns `"HEAD"` when detached, so `has_upstream` errors with "cannot locate local branch 'HEAD'". Check `head_detached()` first.

## Verified NOT bugs
- `git merge`, `pull`, `cherry-pick`, `commit -m`, and `rebase --continue` after a plain pick do not open an editor when run with piped stdio (verified with git 2.50).
- libgit2 `checkout_tree`/`status_file` re-read the index from disk; `staging_diff`/`status_lists` call `index.read(true)`.
- `changes.ts` file-diff race is guarded by `diffToken`; `detail.ts` blame/history/tree use `stillViewing` guards; `log.ts` disconnects its `ResizeObserver`; undo/redo slot management (new action clears redo, undo arms redo, redo re-arms undo) and per-tab isolation are correct.

## Suggested order
1. U1 + U2 (one precondition function in `undo.rs`; no undo during a merge/rebase session; don't record a paused rebase).
2. W2, W3, W1, C1, C2 — each is a short, contained fix with user-visible breakage today.
3. U4, O1, O2, C3.
4. The rest.
